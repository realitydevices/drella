# v0.3: Claude Code as a second agent

v0.2 runs every job with OpenCode. v0.3 adds **Claude Code**, logged in with a Claude
subscription's OAuth token, as a second agent in the same job image. Which agent runs
comes from the model: a model with the `claude-code` interface runs Claude Code, and
every other model runs OpenCode. Numbers in brackets refer to
[decisions.md](decisions.md). Where this page and [v0.2](v0.2.md) differ, this page
wins.

## Done when

1. Store a Claude OAuth token (from `claude setup-token`) as a credential.
2. Register a `claude-code` model naming that credential.
3. Create a job with that model: it runs Claude Code, follows the same rules as an
   OpenCode job (time limits, stop handling, outputs, PR), and its transcript is
   readable.

## The `claude-code` interface

| Field | For a `claude-code` model |
|---|---|
| `interface` | `claude-code` |
| `base_url` | **Not used, and refused if given.** Claude Code talks to Anthropic itself |
| `model_id` | A Claude Code model name, as `claude --model` takes it: an alias such as `sonnet` or `opus`, or a full model ID. Same character rules as any `model_id` (so no `[1m]`-style suffixes) |
| `credential` | **Required:** the name of the credential holding the OAuth token. Never `github` |
| `context_length`, `max_output_tokens`, costs, `notes` | As for any model. The limits aren't passed to Claude Code; they're recorded for comparison |

Every other interface still needs a `base_url`. Jobs snapshot the model as in v0.2,
with no base URL. A credential is stripped and checked as any model key is (v0.2).

**Terms.** What Anthropic's docs say, as of v0.3 (check the pages themselves:
[authentication](https://code.claude.com/docs/en/authentication) and
[legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)):
- `claude setup-token` makes a one-year OAuth token "for CI pipelines, scripts, or other
  environments where interactive browser login isn't available". It "can only make
  model requests", and it only works with Claude Code itself (it's what
  `CLAUDE_CODE_OAUTH_TOKEN` reads).
- Plan usage limits "assume ordinary, individual usage of Claude Code and the Agent SDK".
- Developers may not "route requests through Free, Pro, Max, or Ultra plan credentials
  on behalf of their users", and "may not collect, store, or intermediate Claude.ai
  credentials or session tokens".
- Running Claude Code in a product or service for others ("hosted sandboxes or other
  agent infrastructure") needs Anthropic's Commercial Terms, and "each end user must
  authenticate with their own" API key, subscription or cloud-provider credential.

Drella's position:
- **Your own token, for your own jobs only.** You store your own subscription token,
  and only your jobs can use it: models and credentials are per token (v0.2), so no
  other caller can run on it. That's you running the unmodified Claude Code binary on
  your own subscription, from your own machine.
- **Not for hosting Drella for other people on subscriptions.** A Drella that holds
  other people's subscription tokens, or that runs jobs for others on yours, is outside
  what the subscription allows. If you host Drella for others, they use API keys (the
  `anthropic` interface, v0.2, billed to the key's owner), or you arrange the
  Commercial Terms.
- Jobs count against your plan's usage limits like any other Claude Code use.

## The agent

The adapter for the model's interface names the agent, and the runner passes it to the
pod as `DRELLA_AGENT` (`opencode` or `claude-code`). For Claude Code it also passes the
model (`DRELLA_AGENT_MODEL`). If the image doesn't know the agent, or its settings
are missing (Drella and the job image are different versions), the job fails with a
message saying so. The token reaches the pod as `DRELLA_LLM_KEY` from the
job's Secret, exactly like an API key (v0.2). The wrapper gives it to Claude Code as
`CLAUDE_CODE_OAUTH_TOKEN`, set only in the subshell that runs the agent, so it's never
on a command line.

The wrapper runs:

```
claude -p --model=<model_id> --output-format stream-json --verbose \
  --dangerously-skip-permissions --setting-sources user --strict-mcp-config "<message>"
```

- **Same job rules for both agents.** The message (the prompt plus the standing
  instructions), the soft and hard time limits, stop handling, the provisional and
  final status, redaction, the outputs and the PR check are the same as for OpenCode
  (v0.md, v0.2). The pod runs as uid 1000, which `--dangerously-skip-permissions`
  requires (Claude Code refuses it as root).
- **No preflight check.** An OAuth token can't be checked with a cheap request.
  Claude Code fails within seconds on a bad or expired token, and the job's message
  then carries Claude Code's own reason, e.g. `claude-code exited with 1: Failed to
  authenticate. API Error: 401 OAuth access token is invalid.`
- **Transcript.** Claude Code's output is a stream of JSON events. It's kept whole
  as the output `session.jsonl`, the session record, in place of OpenCode's
  `session.json`. It's redacted as it's recorded and again as it's copied, and it's
  only copied if it's still a regular file (the agent runs as the same user and could
  replace it with a symlink to `/creds/github`); the same goes for reading Claude
  Code's error from it for the job's message. The agent can still write anything it
  likes there, as it can to `/out` (v0.2's redaction gaps). The transcript (and so the live and archived log) is that
  stream turned into readable lines: the agent's text, `-> Tool {input}` for each tool
  call and `<- result` for its result (both cut to 300 characters), and a closing line
  with the number of turns and the time taken. A line that isn't JSON passes through.
- **The image.** Claude Code's native build, pinned (`CLAUDE_CODE_VERSION`) and
  checked against the SHA-256 checksums in that release's manifest. Auto-update,
  telemetry, error reporting and other non-essential traffic are off
  (`DISABLE_AUTOUPDATER`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`,
  `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`). With those off, the only host it
  contacted in testing (with an invalid token, so the session ended at the first
  request) was `api.anthropic.com`. Anthropic's docs say a setup-token "can only make
  model requests", so it can't fetch claude.ai connectors or open Remote Control.

## Security

The same attack classes as v0.2, applied to Claude Code. v0.2's Security section still
holds for both agents: the agent, and everything it runs, can read its keys.

- **The repo can't configure Claude Code.** Claude Code would otherwise load settings
  from the repo: `.claude/settings.json` and `.claude/settings.local.json` can set
  hooks (commands that run by themselves), env vars (e.g. `ANTHROPIC_BASE_URL`, to
  send the token to another server) and an `apiKeyHelper` (a command that supplies the
  key), and `.mcp.json` can start MCP servers (more commands). The wrapper passes
  `--setting-sources user` (no project or local settings) and `--strict-mcp-config`
  (no MCP servers besides ones passed on the command line, and none are). Tested with
  the real Claude Code against a repo shipping all four: without the flags, the hooks,
  the `apiKeyHelper` and the MCP server all ran and the requests went to the repo's
  server; with them, nothing ran and the only requests went to `api.anthropic.com`.
- **Hooks are off as a second layer.** The image's managed settings
  (`/etc/claude-code/managed-settings.json`, which uid 1000 can't change) set
  `disableAllHooks`. In testing that alone stops hooks but not the `apiKeyHelper`,
  env or MCP servers: the flags above are the real control.
- **CLAUDE.md.** With project settings off, Claude Code doesn't load the repo's
  `CLAUDE.md` (tested). The standing instructions already tell the agent to read
  `AGENTS.md`, `CLAUDE.md` and `CONTRIBUTING.md` itself; that content is prompt
  injection, covered in v0.md.
- **The token goes to Anthropic.** The repo can't set env vars or settings (above), and
  the pod's environment is Drella's. The token is redacted from the transcript and
  `session.jsonl` like any key, with the same gaps (v0.2).
- **The user's own settings.** Claude Code still reads user settings from its home
  directory. The image has none, and the agent can write some, but only for a later
  session, and there is none; it already holds the token anyway.
- **Network.** Nothing changes: the job NetworkPolicy already allows the public
  internet, which is where `api.anthropic.com` is.

## Also in v0.3

- **Migration 0003** makes `base_url` optional for models and job snapshots.
  Downgrading to 0002 refuses while a `claude-code` job is queued or running; otherwise
  it deletes `claude-code` models and gives finished `claude-code` jobs an empty base
  URL.

## Out of scope

Choosing the agent independently of the model (e.g. Claude Code with an API key), MCP
servers for the agent, Hermes, and recording usage per job.
