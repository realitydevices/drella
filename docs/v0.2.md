# v0.2: models

v0 jobs named a model by its raw ID plus an endpoint URL, and only endpoints with no API
key worked. v0.2 adds a **models table**: each model is registered once under a short
alias, and jobs name the alias. A model can need an API key, which comes from the
caller's encrypted credentials [19]. Everything else in [v0.md](v0.md) still applies.
Numbers in brackets refer to [decisions.md](decisions.md).

## Done when

1. Register a local model with no key (e.g. Ollama) and a hosted model that needs a key
   (e.g. Anthropic, with the key stored as a credential).
2. Create a job for each by alias. Both run, and each job's pod receives only its own
   model's key.
3. Jobs created before v0.2 still show their model and endpoint.

## Models

A model row:

| Field | What it is |
|---|---|
| `alias` | The name jobs use, e.g. `local-coder`, `claude`. Same rules as a credential name. Unique per token |
| `interface` | How to talk to it: `openai-compatible` or `anthropic` (see Adapters) |
| `base_url` | The API's base URL, e.g. `http://<ollama-host>:11434/v1` or `https://api.anthropic.com/v1`. A trailing `/` is removed. After `http://` or `https://`, only letters, digits and ``. _ ~ : / % ! $ & ' ( ) * + , ; = -`` (write hostnames in punycode). So no whitespace, control characters, `{`, `}`, `[`, `]`, quotes, `\`, `<`, `>`, `^`, `` ` `` or `\|`, and no userinfo (`user@`), query (`?`) or fragment (`#`), which could carry secrets. Must be `https` if the model has a credential |
| `model_id` | The provider's name for the model, e.g. what `ollama list` shows. Only letters, digits and ``. _ ~ : / % ! $ & ' ( ) * + , ; = @ -`` |
| `credential` | Optional: the *name* of the credential holding the API key. Never the key itself, and never `github` |
| `context_length` | Optional: the context window, in tokens (1 to 10,000,000) |
| `max_output_tokens` | Optional: the most the model writes in one reply, in tokens (1 to 10,000,000) |
| `cost_in_per_mtok`, `cost_out_per_mtok` | Optional: price per million input/output tokens, for comparing outcomes later (0 to 100,000, up to 4 decimal places) |
| `notes` | Free text, up to 2000 characters |

API:

| Endpoint | What it does |
|---|---|
| `PUT /models/{alias}` | Create or replace one of your models |
| `GET /models`, `GET /models/{alias}` | List / show your models |
| `DELETE /models/{alias}` | Remove one of your models. Jobs that used it keep their snapshot |

**Models are per token** until O2. A token sees, changes, deletes and uses only the
models it registered; another token's models don't exist for it (404). Two tokens can
each have a model with the same alias. A token can have up to 200 models.

Why: whoever controls a model's endpoint controls the agent, and the agent holds the
job's GitHub token (and, with a repo, can push and open PRs). A model shared between
tokens would let its owner repoint it at any time and take over everyone else's jobs,
even a model with no API key. Shared ("house") models come with O2's roles.

## Jobs

`POST /jobs` takes `{prompt, repo?, model}`, where `model` is an alias. `endpoint` is gone,
and unknown fields are rejected (422), so an old client sending `endpoint` is told.
- The alias is looked up among the caller's own models; an unknown alias is rejected
  (422).
- The model is checked again with today's rules, so a row stored before a rule existed
  can't launch (422, "register it again").
- If the model names a credential, the caller must hold a credential with that name
  (422 otherwise).
- The model's key must be usable as one: a key containing control characters, `"`, `\`,
  `{` or `}` is rejected (422) without echoing it. Quotes, backslashes and control
  characters would break OpenCode's config, and OpenCode would substitute `{env:…}` or
  `{file:…}` in a key.
- Surrounding whitespace is never part of a credential: it's stripped when a credential
  is stored and again when it's read, so a key read from a file with a trailing newline
  is fine, whenever it was stored.
- Validation errors (422) never echo credentials. Request validation errors don't echo the
  rejected value at all; "no model 'x'" names the alias you asked for.
- The job records a **snapshot** of the model as it was when the job was created:
  alias, interface, base URL, model ID, credential name, context length, maximum output
  tokens and costs.
  Changing or deleting the model later doesn't rewrite the job's history.
  `GET /jobs/{id}` shows the snapshot, including the base URL its key was sent to.

Jobs from before v0.2 keep their model ID and endpoint in the snapshot, with interface
`openai-compatible`; their alias is the model ID.

## Credentials

At job creation the key is decrypted (the request carries the token) into the job's
Secret, under the fixed key `_llm-key`. The job gets only what it needs [10]: `github`
for a job with a repo, and the model's key if it has one. Nothing else.

In the pod the key is the environment variable `DRELLA_LLM_KEY`, and only that: the
Secret is mounted as files only for a job with a repo, and then only `github`
(`/creds/github`). OpenCode's config refers to the key as `{env:DRELLA_LLM_KEY}`.

The agent can read its own environment, so it can read the key, as it can the GitHub
token. A prompt-injected agent can leak either (see Security below and in v0.md). Use a
key you can revoke, with a spending limit.

The wrapper replaces both values with `[redacted]` in what OpenCode prints (which
becomes the transcript and the archived log) and in `session.json`. That keeps the keys
out of storage when the agent prints them by accident. It is **not** a barrier against
an agent that wants to store them:
- a key split across lines, or encoded, gets through;
- other files the agent writes to `/out` are uploaded as they are;
- the agent holds the job token, so it can upload outputs or post a status message
  itself, unfiltered;
- it can write straight to the pod's log, which Drella archives;
- `diff.patch` isn't filtered: a key the agent writes into a repo file is in the diff (and
  in the pushed branch);
- keys shorter than 8 characters aren't redacted at all (too likely to match ordinary
  text).

Filtering one very long line that is full of keys is slow; only an agent doing it on
purpose produces that.

## Adapters

One adapter per interface, in code (`drella/adapters.py`). Adding a provider type means
adding an adapter; adding a model is just a row. An adapter produces:
- **The OpenCode config:** a provider named `drella` with the right AI SDK package
  (`@ai-sdk/openai-compatible` or `@ai-sdk/anthropic`), the base URL, and the API key
  as `{env:DRELLA_LLM_KEY}` when the model has a credential. If both `context_length`
  and `max_output_tokens` are set, they're passed as the model's limits; OpenCode
  accepts the limits only as a pair, so neither is passed alone. The agent runs
  `drella/<model_id>`.
- **The preflight check:** a URL and headers. The wrapper calls it before starting the
  agent, so a wrong URL or a rejected key fails the job in seconds rather than after
  OpenCode retries for an hour.
  - `openai-compatible`: `GET <base_url>/models`, with `Authorization: Bearer <key>` if
    there's a key.
  - `anthropic`: `GET <base_url>/models`, with `x-api-key: <key>` and
    `anthropic-version: 2023-06-01`.

Drella renders both and passes them to the job as environment variables
(`DRELLA_OPENCODE_CONFIG`, `DRELLA_PREFLIGHT_URL`, `DRELLA_PREFLIGHT_HEADERS`). Header
values refer to the key as `{key}`, which the wrapper fills in from `DRELLA_LLM_KEY`. The
wrapper has no provider-specific code.

## Security

- **Your jobs use only your models.** Models are per token (see Models), so Drella
  sends your key only to a base URL you set, and your jobs (with your GitHub token)
  talk to an endpoint you chose. Nobody else can repoint them. That's what Drella
  controls; it isn't a promise about where the key ends up: OpenCode follows redirects
  with it (see below, #35), and every process the agent starts (tests, build scripts,
  package install hooks) has the key and the GitHub token in its environment.
- **A model row can't take the GitHub token as its key.** A model can't name the
  `github` credential, or the row would send it to its URL in the API-key header. A
  model with a key needs `https`. (The endpoint you choose still drives the agent, and
  the agent holds the GitHub token: choose endpoints you trust.)
- **git sends the GitHub token only to GitHub.** git's credential helper is set for
  `https://github.com` only, so a submodule, a git dependency or a plain-http remote
  never gets it.
- **The repo can't change the model.** OpenCode also reads config and plugins from the
  project (`opencode.json`, `.opencode/`), and project config would win: a repo could
  point the `drella` provider at its own URL and receive the key, or run a plugin. The
  wrapper sets `OPENCODE_DISABLE_PROJECT_CONFIG=1` for every OpenCode call, which turns
  both off. The only config OpenCode reads is the one Drella rendered (the image has
  no global config, and the environment is Drella's). The same switch stops OpenCode
  loading the repo's `AGENTS.md` / `CLAUDE.md` into the prompt, so for a job with a repo
  the standing instructions tell the agent to read `AGENTS.md`, `CLAUDE.md` and
  `CONTRIBUTING.md` at the repo root, if they exist, and follow their conventions.
  Those files reach the agent as any file in the repo does: that's prompt injection,
  covered in v0.md. The agent itself can write OpenCode config (e.g. in its home
  directory), but it already holds the key.
- **Model rows can't reach into the pod.** OpenCode substitutes `{env:…}` and
  `{file:…}` anywhere in its config, so `{` and `}` are rejected in everything from a
  model row that goes into it.
- **Redirects:** the preflight check doesn't follow redirects. OpenCode does, and
  forwards the key to the redirect's target, even on another host. That adds little
  (whoever controls the base URL already gets the key), but a base URL should be the
  API itself, not something that redirects.

## Network

Hosted APIs are on the public internet, which the job NetworkPolicy already allows. A
model on a private address needs its port opened in `deploy/job-network.yaml`, like
Ollama's 11434 today. Generating the policy from the models table comes later.

## Also in v0.2

- A job without a repo **fails if it produced no outputs**: nothing in `/out` besides the
  transcript and the session record. Only regular files (not symlinks) at the top level
  of `/out` (a convenience, not a security control: the agent can upload anything
  with its job token anyway),
  with names Drella accepts (letters, digits, `.`, `_`, `-`, not starting with `.`), are
  outputs: they're what's uploaded, and what's counted.
- The preflight check uses the URL as it is (`curl -g`).
- **Migration:** existing jobs keep their endpoint and model as an `openai-compatible`
  snapshot. Downgrading to v0.1 refuses while queued or running jobs need `anthropic` or
  a key; otherwise it drops every model, and a later re-upgrade shows old jobs as
  `openai-compatible` with no credential (their interface and key name are lost).
